# ممیزی تطبیق با سند اصلی نیازمندی‌ها

تاریخ ممیزی: ۱۴۰۵/۰۵/۱۶ (۷ اوت ۲۰۲۶)

## دامنه و معماری

- [x] مارکت‌پلیس چندسالن، چندشعبه و چندشهر با سالن زنانه، مردانه و مشترک
- [x] تأیید دستی سالن پیش از انتشار عمومی
- [x] رزرو فوری بدون تأیید دستی سالن و بیعانه پیش‌فرض ۲۰٪
- [x] کارمزد درصدی پس از تکمیل خدمت، کیف پول و تسویه مالک
- [x] React + TypeScript strict، Django REST Framework و SQLite طبق تصمیم صریح کارفرما
- [x] محیط توسعه/production، env نمونه، Swagger و API مستقل مناسب مصرف اپ موبایل

## داده و فرایندهای اصلی

- [x] کاربر، پروفایل، سالن، شعبه، ساعات کاری، خدمت، خدمت شعبه و گالری
- [x] آرایشگر، مهارت، شیفت، مرخصی، عضویت شعبه و سطح دسترسی شعبه‌ای
- [x] رزرو، اقلام رزرو، Hold، کد تخفیف، پرداخت، کیف پول و تسویه
- [x] نظر متصل به رزرو/سالن/آرایشگر با امتیاز کلی، کیفیت، برخورد، نظافت و ارزش خرید
- [x] اعلان، تیکت پشتیبانی و AuditLog عملیات حساس

## موتور رزرو و مالی

- [x] مدت تجمیعی خدمات، آرایشگر واجد شرایط، buffer و grid زمانی
- [x] کنترل ساعات شعبه، شیفت، مرخصی و تداخل رزرو با تراکنش پایگاه داده
- [x] «هر آرایشگر آزاد»، Hold ده‌دقیقه‌ای و پاک‌سازی زمان‌بندی‌شده
- [x] پرداخت بیعانه/کامل، callback درگاه، مانده نقدی، لغو ۲۴ ساعته و no-show
- [x] بازپرداخت به کیف پول، درآمد سالن، کارمزد پلتفرم و پردازش تسویه

## نقش‌ها و مرز دسترسی

- [x] مشتری: رزرو، لغو، پرداخت، کیف پول، نظر و تیکت خودش
- [x] مالک: مدیریت کامل تمام شعبه‌های سالن خودش
- [x] مدیر شعبه: مدیریت همان شعبه و گزارش همان دامنه
- [x] پذیرش: تقویم و ثبت/ویرایش/لغو نوبت شعبه؛ بدون مشتریان و گزارش مالی
- [x] آرایشگر: فقط نوبت‌های متصل به پروفایل خودش
- [x] مدیر کل: دسترسی کامل و مدیریت مرکزی
- [x] مدیر کل ـ تب پشتیبانی: مدیریت تیکت‌ها و مشاهده اطلاعات لازم کاربر/رزرو
- [x] مدیر کل ـ تب مالی: پرداخت، بازپرداخت و پردازش درخواست‌های تسویه

## رابط، عملیات و شواهد

- [x] صفحات عمومی، رزرو، مشتری، پنل سالن و مدیریت بر اساس ۲۷ طرح Stitch
- [x] صفحه تیکت پشتیبانی، عملیات مالی و ثبت نوبت حضوری پذیرش
- [x] Adapter پیامک و پرداخت Mock قابل تعویض با سرویس واقعی
- [x] command قابل اجرای cron برای یادآوری و پاک‌سازی Hold؛ سازگار با هاست اشتراکی و بدون Redis
- [x] فایل محلی media و SQLite با راهنمای backup؛ سازگار با محدودیت هاست اشتراکی
- [x] ۸۴ تست backend، تست فرانت، OpenAPI معتبر، build تولیدی و صفر آسیب‌پذیری npm
- [x] ۱۱ سناریوی مؤثر Playwright شامل رزرو کامل، OTP، مالک، مدیر، پذیرش، مالی، پشتیبانی و تنظیم ساعات رزرو

موارد وابسته به اطلاعات بیرونی و نه نقص پیاده‌سازی: کلید سرویس پیامک، قرارداد/کلید درگاه بانکی، دامنه و TLS نهایی. Adapterها و متغیرهای محیطی لازم برای جایگزینی Mock آماده‌اند.
